## 수집·검증 기준

1. 해당 연도 주최 기관, 지자체, 공식 관광기관의 구체적인 행사 공지를 우선한다. 기관 홈페이지 첫 화면만으로 날짜·비용을 뒷받침하지 않는다.
2. 이름, 연도, 실제 운영일, 장소를 원문에서 확인한 뒤 게시한다. 여러 프로그램 중 하나만 확인했다면 그 프로그램 이름과 범위로 게시한다.
3. 기간 중 휴무나 특정 주말만 운영하면 `dates` 배열을 사용한다. 시작일~종료일을 매일 운영으로 확대 해석하지 않는다.
4. 입장료, 체험비, 식재료비, 예약 보증금을 구분한다. 출처에 없는 요금은 무료로 추정하지 않고 `unknown`으로 둔다. 보증금이 환불될 예정이어도 즉시 무료 참여와 같다고 표시하지 않는다.
5. 예약 기간이 끝난 것은 ‘행사 종료’가 아니다. 반대로 무료 행사가 사전예약 없이 참여 가능하다는 뜻도 아니다. 잔여석은 실시간 확인 기능이 없으므로 안내하지 않는다.
6. 아동 연령·보호자 동반·유모차·주차 등의 조건은 원문 근거가 있을 때만 확정한다. 행사 성격에 따른 방문 전 체크 사항은 사실 확인 내용과 구분해 작성한다.
7. `checkedAt`은 실제 원문을 재확인한 날짜다. 빌드·배포·접속 날짜를 자동 입력하지 않는다. 7일을 초과하면 재확인 안내를 표시한다.
8. 원문이 수정되거나 서로 다른 공지가 충돌하면 더 구체적이고 최근인 안내를 우선 검토하되, 해소되지 않는 항목은 확인 필요로 남긴다. 기존 공지가 접근 불가이면 무조건 최신 검증 완료로 유지하지 않는다.

## 데이터 편집 절차

정본은 `tools/kids-outing-calendar/data.js`다. 필수 필드는 ID, 제목, 지역·주제, 기간, 장소, 요금 상태, 프로그램, 예약 안내, 공식 출처 URL, 확인일, 검증 상태다. `dates`와 `scheduleNote`는 비연속 운영 행사에 사용한다. `feeStatus: free`는 사용자 참여에 필수적인 별도 비용이 없는 것으로 확인된 경우에만 쓴다.

```powershell
# 데이터와 출처를 실제로 확인·수정한 뒤 정적 출처표/JSON-LD 생성
node scripts/build-kids-calendar.mjs
# 생성물과 데이터 일치 및 회귀 검증
node scripts/build-kids-calendar.mjs --check
node --test tests/*.test.mjs
# 공개 자산 빌드 후 외부 저장을 비활성화한 전체 사이트 미리보기
npm run build
npm run preview
```

미리보기 주소: `http://127.0.0.1:4180/tools/kids-outing-calendar/`. 모바일 확인용 `/__mobile?width=360&path=/tools/kids-outing-calendar/`은 360px 프레임이다. 현재 서버는 공개 빌드만 제공하고 Supabase 연결을 로컬 오류 응답으로 바꾼다. 실제 관리자 비밀번호를 입력하지 않는다. 모든 외부 링크나 CDN까지 차단하는 범용 네트워크 sandbox는 아니다. [전체 개편 내역](overhaul-implementation-2026-10-23.md)에서 실행·배포 절차를 함께 확인한다.

수정 후 날짜별 등장/비등장, 지역·주제·무료 필터, 지난 행사, 이번 주말, 월말·연말, 모바일, 공식 링크를 확인한다. source table과 JSON-LD는 같은 데이터에서 생성하므로 HTML만 손으로 수정하지 않는다. JSON-LD는 CollectionPage/ItemList이며, 비연속 행사를 연속 Event 일정처럼 등록하지 않는다. 구조화 데이터가 검색 노출을 보장하지는 않는다.

## 운영 주기 제안

월요일에는 향후 4~6주 신규 공지와 종료 행사를 점검하고, 목요일에는 이번 주말의 시간·예약·우천 변경을 다시 확인한다. 개최 직전 변경이 잦은 행사는 별도 확인한다. 이 일정은 제안이며 자동 실행 작업을 등록한 것은 아니다.

API를 도입해도 원본 피드를 곧바로 ‘검증 완료’로 게시하지 않는다. 수집 → 중복/전년도 데이터 제거 → 공식 공지 대조 → 검토 승인 → 게시 순서로 운영한다. 불명확한 연도나 가격을 AI가 채워 넣지 않도록 미확인 상태를 유지한다. 이후 관리자에 ‘후보 / 검토 / 게시 / 종료’ 단계와 수정 이력을 추가하는 것이 적합하다.

오래된 행사는 날짜로 기본 숨기되 원래 검토일을 보존한다. 검색 유입만을 위해 전년도 URL의 연도·날짜를 올해로 바꾸지 않는다. 지역별 별도 페이지는 충분한 고유 정보와 유지관리 역량이 있을 때만 만든다.

## 저작물·사진 사용

공식 기관 게시물도 이미지·포스터·홍보 문구의 자유로운 상업 이용을 뜻하지 않는다. 출처 링크와 간결한 사실 요약을 사용하고, 사진·포스터를 복제할 때는 저작권자와 공공누리 유형의 상업 이용/변경 허용 여부를 확인한다. 이번 개편에는 외부 포스터를 복제하지 않았다.
