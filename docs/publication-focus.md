# 시뮬랩 공개 콘텐츠 운영 기준

적용일: 2026-10-27

## 중심 주제

가족의 여행·체험·생활정보와 직장인의 월급·퇴직·연차, 가계의 생활비·주거비를 다룬다. 목록을 늘리기보다 신청·예약·계산 뒤의 결정을 돕는 정보를 작성한다.

- 주요 메뉴: 가족 정보 / 평일 생활 / 직장인 계산기 / 생활정보·계산기 / 가족 여행·나들이
- 공개 도구·안내 29개. 그중 핵심 계산기 16개에 직접 작성한 입력 설명·예시·실수·한계·출처를 제공한다.
- 가족 상세 가이드 6개를 홈과 관련 달력 카드에서 연결한다.
- 기존 비핵심 도구 38개는 소스를 보존하고 보관 상태로 둔다. 메뉴·홈 검색·최근 도구 추천·사이트맵에서 제외하며 `noindex,follow`를 제공한다.
- 검색 로봇이 noindex를 읽을 수 있도록 보관 URL을 robots.txt로 차단하지 않는다. 이용자와 검색 로봇에 같은 페이지를 제공한다.
- 보관 페이지는 승인 결과에 따라 자동 재공개하지 않는다. 중심 주제·정확성·실사용 가치를 다시 검토한다.

## 새 글과 도구의 공개 기준

1. 대상과 질문을 하나 정한다. 예: “성인 2명·어린이 1명의 캠핑, 실제 준비할 비용은?”
2. 입력 단위와 적용 범위를 적는다. 계산 결과를 자격 인정·계약 적법성·실시간 가격으로 확대하지 않는다.
3. 따라 할 수 있는 숫자 예시를 작성하고 코드 결과와 대조한다. 가상 금액은 가상 예시라고 표시한다.
4. 자주 틀리는 경계나 조건을 설명한다. 법령·요금·신청 조건은 공식 원문과 확인일을 남긴다.
5. 가족 정보는 장소·연령·보호자 인원·예약 경로·취소·지각·비용의 차이를 다룬다. 방문하지 않았다면 현장 경험을 쓰지 않는다.
6. 자료 확인일과 해설 작성일을 구분한다. 빌드·배포만으로 확인일을 갱신하지 않는다.
7. 같은 틀의 얇은 글을 대량 생성하지 않는다. 달력 사실의 반복을 넘어 비교·준비 순서·구체적인 주의사항을 제공한다.
8. 빈 광고 준비 박스를 넣지 않는다. 글자 수나 페이지 수를 애드센스 승인 조건으로 보장하지 않는다.

## 수정 위치

- 공개 도구의 단일 목록: `assets/js/core-ui.js`의 `SITE_MENU`. `scripts/publication.mjs`가 같은 목록을 읽어 검색·사이트맵·noindex 기준을 맞춘다.
- 계산기 해설: `data/core-tool-guides.mjs` → `scripts/build-core-guides.mjs`.
- 새 계산기 화면: `scripts/build-focused-tools.mjs`. 계산 로직은 각 `tools/{id}/logic.js`에 있으며 균등 정산은 `calculator.js`를 사용한다.
- 가족 원자료: `data/family-info/reviewed.json`. 이번 개편에서 확인 사실·확인 시각은 변경하지 않았다.
- 가족 상세 가이드: `data/family-guides.mjs`. 카드 연결: `assets/js/family-editorial.js`. 둘의 레코드 ID와 경로를 함께 맞춘다.
- 평일 안내: `data/weekday-guides/reviewed.json`.
- 새 통계 ID는 서버의 `record_site_activity` 허용 목록에도 추가한다. 계산 입력값은 전송하지 않는다. 가족 상세 글은 가족 통합 달력의 집계에 포함한다. 보관 페이지는 통계 전송을 중단한다.

## 배포 전 확인

`npm run build`, `node scripts/check-public.mjs`, `npm test`를 실행한다. 새 계산은 날짜 경계·0·할인 한도 등 실제 오류가 발생할 수 있는 조건으로 검증한다. 브라우저에서 데스크톱·모바일 화면, 상세 가이드 연결과 계산 결과를 확인한다. 보관 URL의 noindex와 사이트맵 제외가 일치하는지 확인한다.

2026-10-27 검증: 112개 테스트 통과. 8개 개편·신규 계산기의 모바일 결과와 390px 화면 가로 넘침 여부 확인. Supabase의 추가 12개 ID 수집과 원시 테이블의 익명 조회·직접 쓰기 차단 확인. 서버 테스트 기록은 트랜잭션 롤백으로 남기지 않았다.
