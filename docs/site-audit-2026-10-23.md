# SimuLab 전체 진단과 개선 기획

> 이 문서는 대규모 개편 전의 진단 기록이다. 아래 31/51 canonical 등 초기 수치와 ‘필요’ 표시는 당시 상태이며, 이후 로컬 수정 결과·검증·운영 전환에 필요한 설정은 [대규모 개편 적용 내역](overhaul-implementation-2026-10-23.md)을 기준으로 확인한다. 운영 사이트 반영 여부와는 구분한다.

기준일: 2026-10-23 · 목표: 검색 유입과 광고 수익 확대 · 현재 상태: AdSense 승인 대기, 방문자 거의 없음(운영자 답변)

## 1. 가장 먼저 바꿔야 할 방향

새 도구의 수를 늘리는 것보다 **기존 결과의 정확성, 운영자 신뢰, 모바일 이용 편의**를 먼저 확보해야 한다. 현재는 계산기·건강·세금·통계·게임·축제까지 주제가 넓고, 출처·관리 기준은 균일하지 않다. 부정확한 최신 정보나 실제와 다른 개인정보 설명은 디자인 개선 효과까지 약화시킨다.

추천 순서는 ① 행사 정보 정정과 검증 체계 → ② Supabase 관리자 권한·입력 방어 → ③ 실제 개인정보처리방침·문의 수단 → ④ 대표 페이지의 내용과 모바일 완성도 → ⑤ 검색 성과를 보고 확장이다. AdSense 승인이나 수익을 보장하는 계획은 아니다.

## 3. 이번에 실제 수정한 내용

- 행사 데이터를 공식 공지로 확인한 13개로 정리했다. 요금·예약·참가 조건의 확인 범위를 구분하고 카드와 정적 출처표에 근거를 표시했다.
- 남산 비연속 운영일, 드론 날짜·장소, 바비큐 비용 등 잘못 안내될 수 있는 부분을 바로잡았다. 자세한 근거는 [행사 운영 문서](event-editorial-policy.md)에 있다.
- 실제 한국 날짜, 이번 주말·오늘·월별 보기, 정확한 지역·주제·검색·무료 필터, 종료 행사 선택, 모바일 기본 목록, 조건 공유를 구현했다.
- 실제 API가 아닌 ‘데이터 동기화’ UI를 제거했다. 이전 데이터가 검증된 것처럼 다시 나타나는 브라우저 JSON 가져오기 기능도 제거했다.
- canonical, 실제 존재하는 OG 이미지, 확대 가능한 viewport, 접근성 초점 표시, 정적 출처 표·CollectionPage/ItemList를 추가했다.
- 랭킹/관리자 로그의 HTML 삽입 경로와 tracker 중복 실행을 수정했다. 공통 푸터의 ‘100% Client-Side’ 단정과 배너의 부정확한 데이터 설명을 조정했다.
- 데이터 생성·검증 스크립트, 회귀 테스트 12개, 읽기 전용 Supabase 점검 SQL을 추가했다. DB 정책·실제 관리자 인증 전환은 적용하지 않았다.

## 5. 더 읽기 쉽고 세련된 홈페이지 기획

### 서비스 설명과 홈 구조

첫 문장은 예를 들어 **“계산하고, 비교하고, 주말을 계획하세요.”**처럼 사용자의 행동을 설명한다. ‘엔터프라이즈급’, ‘100% 안전’, ‘60fps’, ‘초정밀 빅데이터’처럼 검증되지 않은 기술 표현은 줄인다. 홈페이지 title도 전체 서비스를 설명하고, 이름 순위 키워드는 이름 도구 페이지에 집중한다.

추천 홈 순서:

1. 짧은 소개 + 전체 도구 검색. 모바일에서 이 영역을 한 화면 내로 유지한다.
2. 자주 찾는 도구 6개. 초기에는 근거 없는 인기 순위 대신 ‘추천 도구’라고 쓴다.
3. ‘이번 주말 나들이’ 섹션: 확인일·대표 3개·행사 목록 진입. 시즌 종료 후 자동으로 옛 행사를 추천하지 않는다.
4. 생활 계산 / 돈 계산 / 통계 살펴보기 / 잠깐 쉬어가기 같은 목적별 진입. 세부 분류는 각 목록 안에 둔다.
5. 최근 검토한 도구·정정 내역, 서비스 소개·문의·개인정보처리방침.

상단 메뉴와 아래 카테고리 막대의 역할을 중복시키지 않는다. 첫 화면에 모든 도구를 펼치지 않고 ‘전체 보기’로 확장한다. 도구 카탈로그를 한 데이터 파일로 관리해 메뉴·카드·개수·사이트맵의 불일치를 줄인다.

### 공통 도구 페이지

H1 → 한 문장 용도 → 입력 → 핵심 결과 → 계산 근거·한계 → 예시 → 관련 도구 2~3개 순서를 기본으로 삼는다. 결과보다 긴 SEO 설명이나 광고가 먼저 나오지 않도록 한다. 금액의 단위와 기준연도, 사용한 세율·가정은 결과 가까이에 둔다.

본문은 모바일 15~16px 수준을 우선 검토하고 충분한 줄 간격과 대비를 확보한다. 이모지·HOT·NEW 배지는 정말 필요한 경우로 줄이고 색의 의미를 통일한다. 확대 허용, 키보드 초점, 입력 label, 오류 안내, 터치 영역을 점검한다. 현재 행사 개편의 차분한 색과 정보 위계를 공통 템플릿의 참고안으로 삼을 수 있다.

## 6. 검색 유입·AdSense 실행 전략

### 처음 집중할 콘텐츠

공식 출처로 유지할 수 있는 행사 달력과, 규칙이 안정적인 생활 도구(평수·단위 변환, 할인율 등)를 우선 대표 페이지로 다듬는다. 금융·세금·건강 도구는 높은 정확성이 필요하므로 관련 기준을 검증할 수 있는 속도로만 확장한다. 게임은 재방문 장치로 운영하고, 검색 유입의 주력으로 가정하지 않는다. 이는 현재 규모에 맞춘 기획 판단이며 검색량 조사 결과는 아니다.

각 도구에는 검색자가 실제로 해결하려는 질문, 입력 예시, 해석, 적용되지 않는 경우를 담는다. 출처·작성/검토일을 공개하되 날짜만 갱신하지 않는다. 같은 데이터에 지역·연도 키워드만 바꾼 빈약한 페이지를 대량 생성하지 않는다. Google은 사람에게 유용하고 신뢰할 수 있는 콘텐츠를 권장하며 선호하는 특정 글자 수가 있다고 안내하지 않는다. [Google 유용한 콘텐츠 지침](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)

### 기술 SEO

대표 URL은 HTTPS와 일관된 trailing slash로 정하고 각 페이지 canonical과 내부 링크를 맞춘다. 실제 HTTP 리디렉션 설정은 Cloudflare에서 확인해야 한다. sitemap에는 정상 공개 페이지만 포함하고 실제 중요한 수정일을 lastmod에 사용한다. 관리자 페이지는 sitemap에서 제외하고 noindex를 확인하되 이것을 보안 수단으로 간주하지 않는다.

description·H1·본문·구조화 데이터가 동일한 내용을 설명해야 한다. SoftwareApplication·FAQPage를 모든 페이지에 기계적으로 넣는 기존 가이드는 수정할 필요가 있다. 검색 기능별 자격 요건을 확인하고, 보이는 내용에 맞는 타입만 사용한다. 구조화 데이터나 메타 설명 길이만으로 상위 노출을 보장할 수 없다. [Google SEO 시작 가이드](https://developers.google.com/search/docs/fundamentals/seo-starter-guide)

Search Console과 네이버 서치어드바이저에서 소유권, sitemap 처리, 대표 5개 URL의 색인 상태·선택 canonical·수집 오류를 확인한다. 폴더에 인증 파일이 있다는 사실만으로 등록 완료라고 단정하지 않는다. 첫 2주에는 실제 쿼리와 노출 기준선을 만들고, 이후 28일 비교로 노출·클릭·CTR과 도구 완료율을 함께 본다. 트래픽이 작은 시기에는 단기 비율 변화로 결론을 내리지 않는다.

### 광고 승인과 수익

승인 전 우선순위는 가치 있는 독자 콘텐츠, 명확한 탐색, 정상 작동, 실제 운영 정보와 정책이다. ‘페이지마다 1,500자면 승인’, ‘도구 개수만 늘리면 승인’ 같은 공식 보장 기준은 없다. [AdSense 사이트 준비 안내](https://support.google.com/adsense/answer/12176698?hl=ko)

광고 슬롯은 우선 결과를 읽은 뒤나 관련 도구 사이 등 자연스러운 구간에 제한적으로 배치한다. 계산·게임 조작 버튼과 가깝게 두지 않고, 빈 광고 영역의 개발 설명을 이용자에게 노출하지 않는다. 광고 전후 모바일 결과 도달률, 오클릭, 화면 밀림을 확인한다. 광고 수를 늘리기 전 방문자가 원하는 결과를 얻는지부터 측정한다.

수익 계획은 추정 단가를 사실로 약속하지 않고 `월 페이지뷰 ÷ 1,000 × 실제 관측 Page RPM`으로 계산한다. 승인 전에는 실측 RPM이 없으므로 금액 목표보다 대표 페이지 품질·색인·노출 증가를 먼저 본다.

## 7. 법적·신뢰 측면 점검

개인정보처리방침은 실제 Supabase 방문/랭킹 처리와 맞아야 한다. 목적·항목·기간·파기·문의·권리행사·위탁/이전 등 해당하는 내용을 확인하고 기재해야 한다. 현재 운영자 이메일이 없으므로 실제 수신 가능한 채널을 먼저 만들어야 한다. [개인정보 보호법 제30조](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1029331583)

AdSense의 Google 및 제3자 쿠키 사용과 이용자 선택 방법을 설명하고, 실제 설정과 문구가 일치하는지 확인한다. EEA·영국·스위스 이용자에게 광고를 제공하는 경우에는 Google의 해당 동의/CMP 요구사항을 검토한다. 기존 ‘확인 및 닫기’ 배너는 적법한 동의 수집이나 광고 차단을 보장하는 CMP가 아니다. [AdSense 개인정보 안내](https://support.google.com/adsense/answer/1348695?hl=ko), [유럽 규정 메시지 안내](https://support.google.com/adsense/answer/16758589?hl=ko)

약관의 ‘민형사상 책임을 일절 지지 않음’, ‘법적 증거로 사용 불가’ 같은 단정은 검토가 필요하다. 면책 문구를 붙여도 모든 책임이 사라지는 것은 아니며, 적용되는 약관 관계에서는 고의·중과실 면책 등이 제한된다. 결과의 용도와 한계를 구체적으로 설명하는 방식으로 고치고 필요하면 전문가에게 검토받는다. [약관규제법 제7조](https://law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0007&lsiSeq=260021&urlMode=lsScJoRltInfoR)

건강·음주·세금 도구는 일반 참고 정보와 개인별 판단을 구분해야 한다. 특히 음주 계산을 실제 운전 가능 판정으로, 세금 추정치를 확정 세액으로 표현하지 않는지 별도 검토한다. 사주·성향 테스트는 검증된 과학적 진단으로 오해되지 않게 성격을 표시한다. 이번 검토는 각 수식의 정확성까지 인증한 것이 아니다.

이름 통계는 고정된 2026 수치가 어느 원자료·집계기간에서 나온 것인지 추적할 자료가 부족하다. 성씨 비율과 이름 빈도로 계산한 풀네임 값은 실제 등록 인원과 다를 수 있다. 원본 표·가공식을 확인하기 전에는 ‘공식 실제 인원’처럼 단정하지 않고 추정 방법과 한계를 표시해야 한다.

공공데이터·공식 포스터도 이용 조건을 확인한다. 광고 사이트는 상업적 이용에 해당할 수 있으므로 공공누리 유형, 상업 이용 제한, 변경 금지와 제3자 권리를 확인한다. 출처 표시만으로 모든 재사용이 허용되는 것은 아니다.

## 9. 배포와 남은 정보

현재 문서는 로컬 수정본 기준이다. GitHub push, 실서비스 배포, Supabase 권한 변경은 아직 수행하지 않았다. `03_Guidelines.md`는 main push 시 자동 배포를 설명하지만 실제 Cloudflare 연결·명령·출력 폴더는 계정에서 확인하지 못했다.

현재 wrangler.json의 `assets.directory`가 `.`이므로 Workers Static Assets용 `.assetsignore`를 추가했다. `.wranglerignore`만으로 파일 제외를 보장하지 않는다. Pages를 쓰는 경우 별도 출력 폴더에 공개 자산만 복사하는 빌드 구성을 권장한다. 어떤 배포 방식이든 내부 보고서·SQL·테스트·환경 파일 URL이 공개되지 않는지 확인해야 한다. [Cloudflare 공식 자산 제외 설정](https://developers.cloudflare.com/workers/static-assets/binding/)

배포 전 `node scripts/build-kids-calendar.mjs --check`, `node --test tests/*.test.mjs`, `git diff --check`를 실행하고 행사 페이지 PC/모바일과 게임 랭킹·관리자 화면의 정상 표시를 확인한다. 실제 DB 권한은 테스트 프로젝트 또는 읽기 전용 점검 결과를 토대로 검증한다. 이후 변경분만 Git에 반영하고 배포된 페이지의 검토일·출처·비용과 내부 파일 미노출을 확인한다.

추가 정보 중 지금 필요한 것은 **Supabase Security Advisor/권한 점검 결과, 프로젝트 지역, 보관기간**이다. 연락처는 아직 없다는 답변을 반영했다. 다음 단계에서는 실제 운영 이메일을 마련하고, Search Console·AdSense의 상태와 Cloudflare 배포 방식만 확인하면 된다. 비밀번호나 service_role 키를 채팅에 보낼 필요는 없다.
