# 전국 행사 달력의 지속 갱신

2026-10-23 지역 보강: 기존 13개에 공식 공지 검토를 마친 29개를 더해 42개 행사·프로그램을 수록했다. 17개 검색지역에 모두 자료가 있지만 전국 모든 행사를 포괄한다는 뜻은 아니다. 검색 기간에 따라 0건인 지역이 생기며, 이는 실제 행사가 없다는 의미가 아니다.

## 현재 운영 방식

API 활용 승인·인증키는 아직 없다. 현재 게시분은 직접 읽은 문체부·한국관광공사 연계 상세 공지, 지자체·문화재단 등 공식 안내를 근거로 작성했다. 세종은 공식 프로그램 이미지에서 장소·시간·연령을 확인했고 가족 대상 날짜만 게시했다. 포스터는 재게시하지 않았다.

정기 검토는 이 프로젝트의 Codex 자동화 **전국 행사 달력 정기 검토**로 월·목 오전 9시(한국 시간)에 활성화했다. 2026-10-23 사용자가 “검증 통과 시 운영 배포까지 허용”을 선택하여, 공식 자료 검토와 테스트를 통과한 변경은 GitHub main 반영·Cloudflare 운영 배포 확인까지 수행하도록 설정했다. 실제 실행은 자동화 실행 기록으로 확인한다. 로컬 자동화가 실행 가능한 환경이 필요하며, 컴퓨터와 앱 상태에 무관하게 24시간 운영되는 서버 작업이라는 뜻은 아니다. API 수집 코드는 준비됐지만 인증키 없이 호출하지 않으며, 수집 후보를 검토 없이 공개 게시하지 않는다.

## 데이터 흐름

1. `data/events/sources.json`의 17개 지역별 공식 출처에서 앞으로 60일의 후보를 찾는다. 자료가 적거나 오래된 지역을 먼저 조사한다. 문체부 목록에 없는 전시·체험은 지역 문화재단 등으로 보강한다.
2. 선택적으로 TourAPI나 공식 표준데이터 CSV를 가져와 **후보**로 정규화한다. 후보는 `scratch/event-candidates-*.json`에만 저장하며 브라우저에 제공하지 않는다.
3. 실제 해당 연도 상세 공지를 읽어 기간·장소·휴무·가격·예약·어린이 조건을 대조한다. 서로 충돌하거나 출처가 불명확하면 `data/events/held.json`에 사유를 남겨 보류한다.
4. 검토를 마친 항목만 `data/events/reviewed.json`에 편집한다. `checkedAt`과 각 출처 확인일은 실제 읽은 날만 쓴다. 수집시각 `fetchedAt`과 바꿔 쓰지 않는다.
5. 테스트·공개 빌드 검증 후 GitHub main에 반영한다. Cloudflare Workers Builds 성공과 실제 사이트의 자료·자산을 확인한다. DB·광고·방문통계 설정은 이 갱신 작업에서 바꾸지 않는다.

공식 메타데이터에도 갱신 시차·부분 프로그램·전년도 설명이 남을 수 있다. 이번에 전주국제그림책도서전은 기간 필드와 본문이 가리키는 주요 행사 기간이 달라 보류했다. 구미라면축제는 공식 공지에 전년도 먹거리 설명이 포함됐다고 명시되어, 확인한 2026 기간·장소만 활용하고 메뉴·체험은 확정하지 않았다.

## 편집 규칙

- 같은 행사에 여러 출처가 있으면 기록을 추가로 만들기보다 `sources`에 근거를 더한다. 후보 중복은 정규화한 제목·동일 기간·지역·장소 또는 500m 이내 좌표로 비교하며, 날짜가 다르면 합치지 않고 보류한다.
- 휴무가 있거나 특정 회차만 운영하면 `dates` 배열을 실제 운영일로 작성하고 `scheduleType: dates`를 쓴다. 시작·종료일은 배열의 처음·마지막 날짜와 일치시킨다.
- 개최기간만 확인했다면 `scheduleType: period`와 안내문을 사용한다. 달력에 기간이 걸려 있다는 사실을 매일 프로그램 운영이나 예약 가능으로 표현하지 않는다.
- 확인된 유료 체험·식음료·보증금은 구분한다. 상품권 환급을 무료로 표현하지 않는다. 가격 미제공은 `unknown`이다. 무료 필터는 기본 입장·참여 기준이며 선택 구매까지 무료라는 뜻이 아니다.
- 취소 공지를 확인하면 `publicationStatus: cancelled`와 취소 근거를 기록한다. 과거 기록을 임의로 올해 일정으로 바꾸지 않는다.
- 출처가 열리지 않으면 확인일을 올리지 않는다. 7일 경과 안내는 원래 확인일을 기준으로 유지한다. 최신 후보가 없어도 이미 검토한 목록을 빈 배열로 덮어쓰지 않는다.
- `tools/kids-outing-calendar/data.js`와 정적 출처 표·JSON-LD는 생성물이다. 원본 JSON을 고친 뒤 빌드한다.

## 실행

```powershell
# 지역 누락·오래된 검토·중복·필드 오류 확인
npm run events:audit

# 코드와 데이터 검증 및 정적 공개 파일 생성
npm test
npm run build
node scripts/check-public.mjs
node scripts/build-event-data.mjs --check
node scripts/build-kids-calendar.mjs --check
npm run preview
```

보고서는 `scratch/event-review-report.json`에 저장한다. 홈페이지는 앞으로 60일 보기·지역별 건수·공식 안내를 제공하고, 홈의 주말 추천은 서로 다른 지역을 우선 선택한다.

## API 승인 이후

한국관광공사 국문 관광정보 서비스의 현재 경로는 `https://apis.data.go.kr/B551011/KorService2/`이며 `searchFestival2`·`areaCode2`를 사용한다. 공공데이터포털 설명상 개발계정 자동승인, 운영계정 심의승인이며 신청 가능 트래픽 안내는 개발계정 1,000이다. 실제 계정의 허용량·운영 승인을 다시 확인한다. 이미지는 활용 유형이 다를 수 있어 이 수집기는 사진을 가져오지 않는다. [공식 API 안내](https://www.data.go.kr/data/15101578/openapi.do)

1. 위 공식 페이지에서 활용신청·운영 조건을 확인한다. 승인 후 `.env.example`을 `.env.local`로 복사하고 인증키를 해당 로컬 파일에 직접 넣는다. 키를 채팅·GitHub 소스·공개 JS에 넣지 않는다.
2. 아래 명령으로 후보 수집만 실행한다. 승인된 실제 키를 이용한 운영 호출은 아직 검증하지 않았으며, 현재 검증은 모의 응답의 페이지 처리·오류·중복 방어 테스트다.

```powershell
node --env-file=.env.local scripts/collect-event-candidates.mjs --provider=tourapi
# 인증키가 없는 기본 실행은 건너뛰며 기존 자료를 변경하지 않는다.
npm run events:collect

# 공공데이터포털에서 내려받은 공식 CSV의 후보 정규화
node scripts/collect-event-candidates.mjs --provider=standard-csv --file=scratch/festivals.csv
```

CSV는 UTF-8/BOM과 EUC-KR 계열을 읽고 따옴표·쉼표·줄바꿈을 처리한다. 공공데이터포털의 문화축제 표준데이터 필드에 맞춘 가져오기이며 공연·공휴일·지도 API를 한꺼번에 연결한 상태가 아니다. 표준데이터의 현행성·이용 조건은 원본 제공 내역을 확인한다. [전국문화축제표준데이터](https://www.data.go.kr/data/15013104/standard.do)

TourAPI는 현재 시작한 행사만 조회하지 않도록 전년도부터 시작일을 조회한 뒤 로컬에서 현재~60일과 겹치는 항목을 추린다. HTTP 오류, 비정상 응답, 페이지 중복·누락·건수 변동·상한 초과 시 전체 수집을 실패 처리해 이전 후보 파일을 유지한다. 이 범위보다 오래전에 시작한 상설 행사는 별도 조사가 필요하다.

## 배포와 인수인계

검증 후 관련 변경만 커밋한다. 원격 main이 달라졌으면 먼저 비교·통합하며 강제 push나 다른 작업 덮어쓰기를 하지 않는다. 배포 성공은 GitHub의 Workers Builds 결과와 실제 `https://simulab.kr/tools/kids-outing-calendar/`에서 확인한다. 내부 JSON·검토 후보·보고서·환경 파일은 dist에 복사하지 않는다.
