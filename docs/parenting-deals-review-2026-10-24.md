# 육아 할인정보 첫 수록 및 자료 이용 검토

> 이 문서는 첫 버전의 이력입니다. 브랜드 행사 달력으로 개편한 현재 수록 범위와 운영 기준은 [브랜드 세일 달력 검토](brand-sale-calendar-2026-10-24.md)를 확인하세요.

검토일: 2026-10-24 KST. 법적 적합성에 대한 확정 의견이나 개별 업체의 이용허락을 대신하지 않는다.

## 배포 범위

- 홈의 첫 콘텐츠에 ‘아이와 가볼 만한 곳’과 ‘육아 할인정보’를 배치한다. 두 정보 페이지 상단에서도 서로 이동할 수 있다.
- 공식 운영몰 10곳을 대조했다. 4곳은 최소한의 사실 요약, 6곳은 공식 안내 링크로 제공한다. ‘10곳 모두 현재 세일 진행’ 또는 ‘모든 조건 검증 완료’라고 홍보하지 않는다.
- 상품 사진·로고·홍보 배너·후기·상세 설명을 사용하지 않는다. 임의의 정상가 대비 할인율, 최저가, 효능·안전 보증, 협찬 후기, 분유·영양제 광고는 추가하지 않는다.
- 직접 연결되는 공식 URL만 사용한다. 구매 수수료·제휴 추적 파라미터가 없다. 기존 AdSense 승인 대기 설정과 광고 스크립트 보류를 유지한다.

## 법령 확인과 운영 판단

1. 저작권법 제2조는 창작적 표현을 저작물로 정의한다. 개별 가격·용량·일자 같은 사실과, 사진·홍보문·배너의 창작적 표현을 구별해야 한다. 단순히 ‘출처를 적었다’는 이유만으로 복제 허락이 생기지 않는다. 제7조의 사실 전달 시사보도 제외를 쇼핑몰 콘텐츠 전체에 일반화하지 않는다.
2. 저작권법 제93조 제2항은 작은 부분도 반복적·체계적으로 이용해 정상 이용과 충돌하거나 이익을 부당하게 해치는 경우를 규율한다. 상품 목록 전체·판매 DB를 복제하지 않고 공개된 소수 항목을 편집 검토한다. 하루마다 임의 스크레이퍼를 돌리는 방식은 도입하지 않았다. 향후 API·정기 수집은 약관·데이터 이용허락·호출 제한을 별도로 확인한다. 수동 수집이라고 항상 적법한 것은 아니다.
3. 몰별 약관은 저작권과 별도의 쟁점이다. 공개 열람이 상업적 재게시 허락을 뜻하지 않는다. 광범위한 영리 재이용 제한이 있거나 전문 확인을 못 한 곳은 세부 혜택을 전재하지 않는다. 아래의 facts-only 판단 역시 허락을 확보했다는 의미가 아니며, 권리 주장·약관 변경·분쟁 가능성이 있으면 해당 요약을 중단하고 링크 안내로 전환해야 한다.
4. 공정거래위원회 추천·보증 심사지침의 현행본은 2026-06-01 시행, 예규 제499호다. 협찬·상품 제공·제휴 수수료 등 경제적 관계가 생기면 게시물 제목 또는 첫 부분과 해당 안내 가까이에 명확히 표시한다. 현재 페이지는 직접 사용한 후기나 추천·보증을 가장하지 않는다. 사이트 배너 광고와 몰별 제휴 관계는 별도로 관리한다.
5. 적립금·사은품은 결제금액에서 차감하지 않는다. 신규회원 쿠폰을 모두가 받을 수 있는 가격으로 쓰지 않는다. 종료일 미공개를 상시 진행으로 추정하지 않으며 실제 재고·최종 결제 가격은 조회하지 않았다고 표시한다.

## 유지보수

- 편집 원본은 `data/deals/shops.json`, 생성물은 `tools/parenting-deals/data.js`와 정적 HTML이다. 빌드는 형식·검토시각·공식 호스트·권리 상태를 검증하며 확인 시각을 바꾸지 않는다.
- `npm run deals:audit`로 구조와 재검토 상태를 점검한다. 외부몰을 호출하거나 허가 없는 데이터를 자동 게시하지 않는다.
- 표시가격은 24시간, 회원쿠폰은 7일 재검토 기준이다. 기준 경과·종료·시작 전·미검토 상태에서는 가격 강조와 상세 조건을 숨긴다. 열린 페이지에서도 매분 및 다시 활성화될 때 상태를 갱신한다.
- JS가 꺼져도 출처·검토시각·확인 당시 기록이라는 안내가 있는 정적 목록을 볼 수 있다. 새 빌드 시점에도 이미 오래된 가격은 숨긴다. 정적 HTML에 남는 과거 기록이 실시간 구매 조건을 의미하지 않는다.
- 새 항목은 검증된 운영사, 정확한 원문 URL, 실제 검토 시각, 최소 구매·대상·배송·기간·권리 검토 기록이 있어야 한다. 상품 수를 채우려고 미확인 수치를 만들지 않는다.
- 정기 외부 수집 작업이나 제휴 계정은 생성하지 않았다. 원문 재이용이 필요한 몰은 운영자가 허락·제휴 범위를 확인한 뒤 확장할 수 있다. 업체에 연락을 보내거나 계약을 체결하지 않았다.
- 연락 가능한 운영 이메일은 여전히 사용자 확인이 필요하다. 기존 ‘준비 중’ 안내를 유지했으며 사적 계정 이메일을 공개 연락처로 사용하지 않았다.
- Supabase 운영 DB 보안 적용은 사용자가 후순위로 정한 기존 작업이므로 이번 변경에 포함하지 않는다.
