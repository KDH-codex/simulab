# 할인·쇼핑 탭 운영

2026-11-08 사용자가 기획·출처 검토안의 실행을 승인했다. `/sales/`와 `/sales/{id}/`를 축제 사이트 공통 헤더에 추가했다. 다른 생활정보 분야의 중지 상태는 변경하지 않는다.

## 정본과 표시

- `data/deals/reviewed.json`을 기존 세일 달력과 공유한다. `shopping`이 있는 검토 완료 기록만 새 탭에 표시한다. 기존 검토·보류 기록과 실제 확인일을 보존한다.
- `brandId`는 검증에 사용하는 공식 발행처 ID다. `shopping.retailerId`가 이 ID와 일치해야 한다. 실제 상품 브랜드는 `shopping.brand/brandCode`, 지점은 `storeScope/specificStore`, 유통 형태는 `kind/format`, 권역은 `area`로 구분한다.
- 나이키 공식몰과 신세계사이먼 여주 나이키 매장 행사는 다른 적용 범위다. 하나의 지점 공지를 다른 점포·전국 브랜드 행사로 복제하지 않는다.
- 31일 이내 기간 한정 대표 세일 수록 기준을 유지한다. 긴 기간을 임의로 잘라 넣지 않는다. 할인·쿠폰·적립·사은품·배송·할부 조건을 섞거나 할인율을 더하지 않는다.
- 날짜는 연도까지 원문으로 확인한다. 시작·종료 시각이 없으면 만들어 쓰지 않는다. 품목별 기간·제외일·쿠폰 적용 기간이 다르면 조건에 명시한다.
- 새 탭의 검토 유효시간은 기록별 `shopping.reviewWithinHours`다. 초기 기록은 48시간이다. 재확인 필요·종료 항목은 기본 진행 목록에서 제외하며, 사용자가 보관함이나 ‘지난 행사·재확인’을 선택하면 상태와 함께 볼 수 있다.
- 네 가지 추가 언어의 이름과 요약은 `shopping.locales`에 기록한다. 세부 조건과 지점은 한국어 원문으로 표시하고 번역 범위를 안내한다. 신규 기록은 번역과 범위를 함께 검증한다.
- 공식 이미지·로고·전단을 복제하지 않고 자체 안내 카드를 사용한다. 상품 사진처럼 표현하지 않는다. 검증되지 않은 인기·최저가·재고·쿠폰 잔여 수량은 표시하지 않는다.

## 후보 수집과 갱신

1. 최신 원격 main과 Git 변경을 확인하고 별도 작업트리에서 진행한다. 다른 작업을 덮어쓰거나 강제 push하지 않는다.
2. `data/deals/shopping-discovery.json`의 출처와 실제 공지에서 이용 범위를 확인한다. `npm run shopping:collect`는 승인된 공개 목록을 출처당 한 번 읽고 `scratch/shopping-candidates.json`에 후보만 저장한다.
3. 수집기는 로그인·앱 쿠폰함·CAPTCHA·403 제한을 우회하지 않는다. 실패를 ‘세일 없음’으로 바꾸지 않으며, 원문 조회 성공이나 변경 감지만으로 정본·확인일을 갱신하지 않는다.
4. 후보의 공식 상세를 읽어 연도·기간·지점·채널·회원·카드·수량·금액·중복·제외 조건을 대조한다. 검색 요약이나 목록만 확인한 자료는 보류한다. 다른 검토자가 원문을 재대조할 수 있도록 URL·실제 시각·확인 필드를 검토 기록에 남긴다.
5. 읽고 검증한 항목만 `reviewed.json`에 추가·수정한다. 임의로 모든 출처의 `checkedAt`를 현재 시각으로 바꾸지 않는다. 원문을 다시 읽지 않은 기존 자료는 보존한다.
6. `npm run deals:audit`, `npm run build`, `npm test`, `node scripts/check-public.mjs`를 실행한다. 필요하면 `node scripts/build-event-data.mjs --check`, `node scripts/build-kids-calendar.mjs --check`로 축제 데이터도 확인한다.
7. 홈·축제 메뉴·언어·할인 필터·상세·별도 보관함을 검증한다. 특히 모바일 320/390px, 오늘 종료와 날짜 경계, 48시간 경과, 저장소 차단, 지점과 온라인 혼동, 회원·카드 조건을 확인한다.
8. 관련 소스·정본만 커밋하고 일반 main push 후 Cloudflare 성공과 실제 `/sales/`·새 상세 URL·스크립트·사이트맵 반영을 확인한다. 수집·검증·배포를 구분해 보고한다.

현재 기능은 실행 시 후보를 수집하는 CLI와 검토 후 배포하는 흐름이다. 24시간 실시간 수집·자동 승인·정기 실행을 제공한다고 표시하지 않는다. 기존 예약 작업을 임의로 재개하지 않는다. 향후 정기 실행이 요청되면 기존 관련 예약을 확인하고 중복 없이 연결한다.

## 빌드와 테스트

축제 전용 빌드 분기에 기존 세일 생성기와 `build-sales-page.mjs`만 추가했다. 다른 중지 카테고리를 활성화하지 않는다. `/sales/`와 상세는 정적 HTML·자체 canonical을 가지며, 사이트맵과 언어 링크에 포함된다. 행사별 `SaleEvent`나 가격·재고 구조화 데이터를 추정해 넣지 않는다.

DOM 테스트는 외부 사이트를 열지 않고 생성 HTML과 실제 클라이언트 모듈로 필터·대화상자·별도 보관함·5개 언어·저장소 차단을 검사한다. 실제 브라우저 화면 검증과 다르다. 이번 실행에서는 Work의 로컬 브라우저가 꺼져 있어 시각 검증을 수행하지 못했다.
