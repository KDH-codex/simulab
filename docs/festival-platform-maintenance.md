# 이번주축제: 화면 구조와 후속 정보 갱신

2026-11-04 사용자 변경: **홈페이지 구조를 먼저 완성·검증·배포하고, 그 구조에 필요한 축제·행사 정보만 수집한다.** 브랜드 세일과 나머지 8개 분야의 정기 사이트 갱신은 일시정지한다. 다른 분야의 정본과 실제 확인시각은 보존한다. 이 문서가 기존 9분야 운영 순서보다 우선한다.

## 공개 구조

새 탭이나 축제 화면을 추가할 때 [축제 UI 기준](festival-ui-standard.md)의 제목, 색상, 모션, 모바일 검증 규칙을 적용한다.

| 경로 | 역할 | 필요한 정보 |
| --- | --- | --- |
| / | 대표 축제, 테마·지역 필터, 보관함, 이번 주말 | 검증된 행사 ID·제목·지역·테마·일정·비용 상태, 이용 조건이 확인된 이미지 |
| /map/ | 7개 권역의 수록 일정 탐색 | 기존 17개 원본 지역 → model.js의 7개 REGION_GROUPS. 실제 좌표 없는 핀·거리·GPS 탐색 금지 |
| /calendar/ | 월간 달력·주차 선택·날짜별 목록·테마 피드 | 개최 기간과 지정 운영일 구분. 신청기간을 개최일로 사용하지 않는다 |
| /curation/ | 한국시간 이번 토·일에 겹치는 일정 | 실제 운영일을 기준으로 자동 선택. 기간형 공지는 운영일 확인 안내 |
| /events/{id}/ | 공유·검색 가능한 상세안내 | 일정·프로그램 → 예약·비용 → 장소 검색 → 공식 출처와 확인일 |
| /tools/kids-outing-calendar/ | 기존 유입 주소 유지 | 같은 축제 정본. 기존 링크·검색 유입을 깨뜨리지 않는다 |

주요 메뉴에 가족 지원·세일·계산기·게임을 섞지 않는다. 기존 자료는 /library/에서 보관한다. 보관함은 이 기기의 localStorage이며 예약·로그인·알림이 아니다.

## 정본과 공개 규칙

- 축제 정본은 **data/events/reviewed.json**. 새 화면과 기존 달력이 함께 읽는다. 다른 가족 정보 정본으로 대체하거나 화면별로 복사하지 않는다.
- 필수 항목: id, title, region, theme, startDate, endDate, location, time, program, feeStatus, fee, booking, familyNote, verificationStatus, checkedAt, sources.
- dates: 실제 지정 운영일을 오름차순·중복 없이 기록한다. scheduleType=period는 기간 공지이며 scheduleNote에 휴관·회차·미확인 운영일을 설명한다. 매일 운영 또는 상시 운영으로 단정하지 않는다.
- 접수 시작·마감과 실제 이용 회차는 별개다. 현재 정본에 독립 필드가 없는 세부 신청·예약·대상·취소 조건은 booking/familyNote/scheduleNote 및 공식 sources.facts에 보존한다. 필드 확장이 필요하면 모델·테스트·공개 피드까지 함께 변경한다.
- 비용은 무료·부분 유료·유료·미확인을 구분하고 사전·현장·할인가·보증금·선택 체험 비용을 같은 가격으로 합치지 않는다. unknown을 무료로 바꾸지 않는다.
- sources에 공식 상세 URL, 발행기관, 제목, 직접 확인한 사실과 실제 확인일을 남긴다. 필드별 확인 요약은 사실 검토 기록에 남긴다. 근거 없는 날씨·주차·유모차 접근성·인기·좋아요·잔여 좌석·가격을 생성하지 않는다.
- data/events/images.json: src, kind, credit, creditUrl, licenseUrl를 유지한다. context는 반드시 **주제 참고 · 현장 사진 아님**으로 표시한다. 공식 사진·포스터도 재사용 조건 확인 후 추가한다. 미확보 사진은 테마 일러스트로 대체한다.
- 검증된 좌표가 없는 현재 지도는 권역 선택용 개략도다. 그림의 점·경계를 실제 위치·행정경계·행사 좌표로 설명하지 않는다.
- 기본 탐색은 한국시간 오늘부터 60일, 달력은 선택한 달이다. 0건은 수록 정보가 없다는 뜻이며 해당 지역의 실제 행사 0건을 뜻하지 않는다.
- 빌드·배포·날짜 필터는 사실 검증이 아니다. 원문을 읽지 않고 checkedAt/verifiedAt를 갱신하지 않는다.

## 후속 정기 작업

기존 automation 한 개를 축제 전용으로 유지한다. 일정은 화요일 19시 KST, 로컬 PC·Codex 실행 가능 조건은 그대로다. 다른 8개 사이트 갱신 예약은 PAUSED. 수·목 블로그 원고 예약은 자동 게시하지 않으며 축제·행사 후보만 검토하고 최대 2편 제한을 유지한다.

1. 먼저 최신 원격 main에 새 화면 구조가 배포되어 있는지 확인한다. 구조가 미완료·미배포이면 내용 수집·정본 수정·배포를 선행하지 않는다.
2. Git 상태와 최신 main을 확인하고 다른 작업을 보존한다. 매 실행 고유 runId 하나를 사용한다.
3. npm run family:audit -- --category=festivals 로 기존 자료를 살핀다.
4. 여러 권역의 지자체·문화재단·공식 축제 주최처에서 **최소 15개의 서로 다른 공식 상세 공지**를 실제 읽는다. 검색 요약·홈페이지·중복·원문 접속 실패는 제외한다. API 키가 없는 현재는 공식 원문 검토 방식이며 실시간 무인 API 수집이라고 설명하지 않는다.
5. 해당 연도, 실제 개최일·회차, 이용시간·대상, 연령·거주·회원 조건, 비용·접수·예약·취소를 확인한다. 공개 유효 정보 15건 이상을 기본 목표로 하되 확인되지 않은 자료는 보류한다. 전국 공지를 지역별로 복제하지 않는다.
6. data/family-info/research.json 에 categoryId=festivals, runId, 공식 상세 URL·제목·실제 확인시각·detailReviewed·outcome·근거 요약·recordId를 남긴다. 기존 정본 변경은 확인한 필드만 적용한다. state의 festivals만 수정하고 공급자 실패와 확인된 0건을 구분한다.
7. npm run family:audit -- --category=festivals --run=이번실행ID --require-minimum 을 실행한다. 종료코드 2는 15건 미달이다. 신규/기존 재검증/보류/탈락/접근 실패와 공개 유효 수·15건 대비 부족분을 구분한다.
8. npm test, npm run build, node scripts/check-public.mjs, node scripts/build-event-data.mjs --check, node scripts/build-kids-calendar.mjs --check. 홈·지도·달력·상세·모달·보관함·모바일·빈 결과를 화면에서 검증한다.
9. 관련 변경만 커밋하고 최신 main과 안전하게 통합한 뒤 일반 push. 강제 push 금지. 기존 GitHub main → Cloudflare를 사용한다. GitHub 반영·Cloudflare 성공·실제 운영 반영을 각각 확인한다.
10. node scripts/verify-family-deployment.mjs 와 새 축제 화면의 실제 운영 응답·데이터 일치 여부를 확인한다. 수집·검증·배포 실패는 완료로 보고하지 않는다.

출처별 재시도 2회 이내, 실행 3시간 이내. 로그인·캡차·접근 제한을 우회하지 않는다. 새 과금·인증키·호스팅을 켜지 않는다. Supabase·관리자·광고·방문통계·연락처는 변경하지 않는다.
