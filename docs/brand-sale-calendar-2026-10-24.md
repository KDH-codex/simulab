## 수록 기준

- 시작일과 종료일이 공식 원문에서 확인된 **31일 이내** 행사만 수록한다. 양 끝 날짜를 포함해 계산하며, 긴 행사 기간을 임의로 잘라 기준에 맞추지 않는다.
- 브랜드 대표 행사, 여러 품목군의 쇼핑 행사 또는 공식 주요 카테고리 세일을 대상으로 한다. 단일 상품 쿠폰·출시 특가·단일 방송, 일반 회원 가입 혜택, 매월 카드사 할부 안내, 상시 아울렛·가격인하, 장기 배송 지원은 제외한다.
- 기간이 있는 회원 대상 대표 세일은 회원 조건을 표시해 수록할 수 있다. 예: 이케아 단기 거실·수납 세일. 일반 가입 쿠폰과 혼동하지 않는다.
- 전체 행사·개별 쿠폰·타임 특가의 기간이 다르면 확인한 범위를 명시한다. 쿠폰 기간만 확인한 경우 전체 행사 기간이라고 보장하지 않는다.
- 행사당 가격·쿠폰·적립·사은품을 합쳐 할인율을 만들지 않는다. ‘최대’ 할인율을 전체 품목 할인처럼 쓰지 않는다.
- 확인된 단기 대표 세일이 없거나 날짜를 확정하지 못한 브랜드는 ‘추가 확인’으로 둔다. 이를 ‘세일 없음’이라고 단정하거나 전년도 일정으로 채우지 않는다.

모델의 `MAX_SALE_DAYS`, `calendarExclusionReason`, `isCalendarEligible`가 빌드·목록·달력 모두에서 이 기준을 적용한다. `publicationStatus:reviewed`로 잘못 바꾸어도 분류·기간이 맞지 않으면 빌드 검증에 실패하고 화면 필터에서도 제외된다.

## 원본과 검증

- `data/deals/sources.json`: 고정 확인 브랜드, 공식 호스트, 검색 별칭, 확인 범위 메모, 실제 출처 확인 시각.
- `data/deals/reviewed.json`: 행사 날짜·조건·실제 원문 확인 시각, `campaignKind`, `campaignScope`, 게재 상태와 보류 이유.
- `tools/parenting-deals/data.js`와 HTML은 생성물이다. 직접 수정하지 않는다.
- `npm run deals:audit`: 형식·기간·수록 정책·보류 이유 점검. 외부 호출이나 확인 시각 갱신은 하지 않는다.
- `npm run build`, `npm test`, `node scripts/check-public.mjs`, `node scripts/build-publishing-ui.mjs --check` 후 모바일·데스크톱을 확인한다.
- 같은 공식 캠페인의 중복 등록을 피한다. 여러 브랜드가 같은 운영몰을 써도 해당 브랜드 적용이 확인되지 않으면 각 브랜드의 세일로 복제하지 않는다.

실제 확인 시각은 데이터에 보존한다. 배포·빌드·자동 상태 갱신은 시각을 변경하지 않는다. 종료 판정은 한국 시각을 기준으로 한다. ‘23:59까지’처럼 분 단위 마감과 컬리의 ‘11시 전까지’처럼 시각 경계를 구분한다. 확인 후 7일을 넘으면 ‘재확인 필요’로 바뀌고 진행 중·임박 집계에서 제외된다.

## 정기 추적 절차

기존 월·목 오전 9시(한국 시각) 정기 검토에 이 기준과 고정 브랜드 목록을 함께 사용한다. 이는 그때 공식 공지를 읽고 검토하는 작업이며, 웹페이지가 자체적으로 모든 몰을 실시간 수집하는 API는 아니다.

1. 작업 폴더·현재 Git 상태·원격 main을 확인한다. 다른 변경을 덮어쓰거나 강제 push하지 않는다.
2. 위 두 원본과 `deals:audit`를 읽고, 사용자 지정 브랜드 17개·곧 종료되는 세일·오래된 확인일을 우선 검토한다. 고정 31개 브랜드의 공식 페이지·자사 공지·공식 SNS에서 해당 연도 자료를 찾는다.
3. 시작·종료·채널·대상·쿠폰 조건·취소·변경을 읽어 대조한다. 검색 노출, 제품 카드의 날짜, URL 폴더 날짜만으로 행사 기간을 만들지 않는다.
4. 접근 제한·캡차·로그인이 필요한 내용은 우회하지 않는다. 확인 실패를 ‘세일 없음’으로 단정하거나 기존 목록을 비우지 않는다. 날짜 미확인은 메모·보류로 남긴다.
5. 약관·출처·권리 범위도 검토한다. 원문을 실제로 다시 읽은 항목만 확인일을 갱신한다.
6. 모델 검증·전체 테스트·빌드·공개 경로 검증·화면 점검을 통과한 변경만 커밋·main 일반 push한다. Cloudflare 빌드 성공과 실제 운영 페이지를 확인한다.
7. Supabase·광고·방문통계·관리자 권한·사용자 연락처는 이 작업에서 변경하지 않는다.

## 자료 이용과 남은 한계

공개 공지나 출처 표기만으로 영리 재이용 허락이 생기는 것은 아니다. 최소한의 행사 일정·조건을 자체 문장으로 정리한 범위이며, 업체의 포괄적 허락이나 법적 적합성을 확정한 서비스가 아니다.

- [저작권법 제93조](https://law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0093&lsiSeq=283335&urlMode=lsScJoRltInfoR)의 반복적·체계적인 데이터 이용 문제를 고려한다. 대량 상품 DB 수집·미러링은 도입하지 않는다.
- 사진·로고·배너·상품 설명·후기·개별 가격표·전체 상품 목록을 복제하지 않는다. 광범위한 약관상 이용 제한과 권리 주장은 계속 검토하며 필요하면 항목을 보류하고 링크 안내로 전환한다.
- 링크는 제휴 추적 코드 없이 공식 원문으로 연결하며 구매 수수료가 없다. 향후 제휴·협찬이 생기면 관계를 명확히 표시한다.
- 공개 문의 이메일과 Supabase 운영 보안 적용은 기존 후순위 과제다. 이번 작업으로 완료했다고 표시하지 않는다.
