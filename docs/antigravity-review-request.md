# 독립 검토 요청 · 이번주 축제

당신은 이번주 축제 웹사이트의 독립 리뷰어다. 앞선 구현자의 결론을 그대로 승인하지 말고, 사용자 요구사항과 실제 동작을 기준으로 디자인·UI·UX·모션·이펙트의 누락과 결함을 조사하라. 이번 작업의 산출물은 검토 보고서와 실행계획 보완안이다. 코드 구현, 데이터 수정, 커밋, 배포, 새 서비스 연결은 하지 않는다. 다른 에이전트를 추가로 실행하지 않는다. 보고서 전체를 최종 응답으로 반환한다.

## 최우선 검토 관점 · 사용자 추가 지시

이번 검토의 중심은 기능 오류 찾기만이 아니다. Stitch에 구현된 중요한 디자인 의도·구도·톤앤매너를 현재 사이트가 얼마나 살렸는지 평가하고, **디자인·이미지·상호작용을 적재적소에 배치하여 더 완성도 높은 웹사이트를 만드는 실행계획**을 제안한다. 사용자가 첨부한 UI·모션 치트시트 3장도 `references/user-motion/`에서 직접 열어 참고하라.

- 비교: Stitch의 홈·지도·달력·모달 각각에서 정보 위계, 시선의 흐름, 여백, 카드 밀도, 큰 이미지와 보조 이미지 비율, 컬러 강조, 한국어 타이포그래피, 버튼 체계, 모바일 구도가 현재 구현에서 유지/개선/손실된 부분을 짚는다. 원본의 단순 복제가 최종 목표는 아니다.
- 정적 이미지와 실제 사진: 대표 영역·추천 카드·목록·상세·빈 화면에 어떤 종류의 이미지가 적합한지, 크롭·비율·텍스트 대비·출처 표기·성능까지 위치별로 제안한다. 공식 행사 사진·포스터가 없으면 필요한 자산을 과제로 기록한다. 참고 사진을 실제 현장 사진처럼 보이게 하지 않는다.
- 모션: 등장, 전환, 선택, 피드백, 로딩, 종료의 목적이 분명한지 본다. 각 적용 제안은 대상 요소, 발생 조건, 변화 속성, duration/delay/easing, 모바일·키보드 동작, prefers-reduced-motion 대안을 포함한다. 단순히 ‘GSAP 도입’ 또는 ‘애니메이션 강화’라고만 쓰지 않는다.
- 효과의 절제: 첨부한 64개 개념은 전부 추가하라는 지시가 아니다. 현재 사용자 흐름에 맞는 효과를 선택하고 ‘적합 / 선택적 / 부적합’의 이유를 남긴다. 이 참고자료의 어두운 배경색은 사이트 디자인으로 가져오지 않는다. 사이트의 밝고 따뜻한 오렌지·라벤더 톤을 유지한다.
- 특히 살필 요소: hero와 split/bento 구성, 카드 배치와 hover/focus, responsive/sidebar/sticky header, tabs/segmented control, modal·모바일 bottom sheet, carousel와 scroll snap, stagger/scroll reveal, fade/slide/scale/easing, micro-interaction와 toast, skeleton·실패·빈 상태.
- 신중히 선택할 요소: parallax·page/shared-element transition·spring·text animation·spotlight·gradient·scroll progress. 탐색성을 실제로 개선할 때만 제안한다.
- 현재 흐름에 필요성이 입증되지 않은 infinite scroll·command palette·wizard·OTP·drag & drop·custom cursor·magnetic button·3D tilt·confetti·무한 반복 효과 등은 숫자를 채우거나 화려함을 위해 넣지 않는다.
- 디자인 개선 제안은 결함과 별도로 적극적으로 제시한다. ‘동작함’과 ‘잘 디자인됨’을 같은 판정으로 합치지 않는다. 홈 첫 화면, 필터 통과, 주간 달력, 모바일 상세의 네 가지 핵심 장면에 대해 구체적인 개선 방향을 제시한다.

실행 모델은 사용자가 지정한 **Argon**, effort는 **medium**이다. 다른 모델·에포트로 대체하지 않는다. 실행 환경에서 확인되지 않는 값은 보고서에 명확히 구분한다.

## 확정된 요구사항

1. 브랜드 표기는 **이번주 축제**다. 브랜드·‘이번 주 어디갈까?’ 큰 문구는 샌드박스 어그로체, 제목은 페이퍼로지, 일반 글씨는 프리텐다드다. 이전 본문 서체 요구보다 후속 프리텐다드 요청이 우선한다.
2. 색상: 주황 #F97316, 인디고 #6366F1, 보라 #7C3AED. 불꽃놀이 아이콘과 Stitch의 밝은 축제 탐색 컨셉을 유지한다.
3. 카드 피드는 스크롤 진입 시 순차 등장한다. 내용 접근성, 초기 표시 실패, 재필터 후 등장, 모션 줄이기를 확인한다.
4. 대표 카드는 3초마다 전환하며 이전·다음 버튼도 같은 전환 효과를 사용한다. 읽기 중 정지, 일시정지 버튼, 포커스, 빠른 연속 클릭, 모션 줄이기를 확인한다.
5. 카드와 대표 영역의 태그는 실제 행사 정보에서 도출하고 버튼 형태를 유지한다. 클릭·해제·조건 초기화가 결과와 연결되어야 한다.
6. 각 페이지에서 원래 필터를 지난 뒤 작은 필터가 상단에 고정된다. 고정 전환 시 레이아웃 점프, 콘텐츠 가림, 필터 상태 불일치, 모바일 조작을 확인한다.
7. 달력은 월간 기본값, 월간/주간 단일 세그먼트다. 왼쪽 주차 선택으로 주간 일정과 날짜별 가로 피드가 연결되어야 한다. 월 경계·긴 제목·행사 없음·선택 상태도 확인한다.
8. 날씨는 대표 도시 예보다. 제공 범위·갱신 시각·실패·예보 없음·날짜별 기준 시각이 명확해야 한다. 행사장 GPS·실황·일 최고최저로 오해시키지 않는다.
9. 지역은 서울 / 경기지역 / 강원지역 / 충청지역 / 전라지역 / 경상지역 / 제주지역이다. 원본 지역의 그룹 연결을 보존한다.

- 홈 `/`, 지도 `/map/`, 달력 `/calendar/`, 이번 주말 `/curation/`, 실제 카드에서 연 상세 페이지와 상세 모달.

- 첫 화면 정보 위계, 글자 크기·줄바꿈, 색 대비, 간격, 이미지 비중, 버튼 우선순위, 빈 결과, 긴 제목, 보관함, 되돌아가기, 모달 포커스와 Escape.
- 지역·테마·태그 선택 → 카드 열기 → 공식 출처 확인 → 달력 주차·날짜 선택의 실제 사용자 흐름.
- 자동·수동 전환, 스크롤 등장, 고정 필터, 모션 줄이기는 실제 조작으로 검증한다. 정지 스크린샷이나 코드만으로 모션 완료라고 판단하지 않는다.
- 브라우저 도구가 없거나 접근에 실패하면 정적 검토만 수행하고 화면·모션은 미검증으로 남긴다. 접근 제한·인증·캡차를 우회하지 않는다.

## 범위 보존

이번 검토는 홈페이지 구조·UI에 한정한다. 축제 정보가 부족하거나 오래되었다면 별도 콘텐츠 과제로 기록한다. 확인일을 일괄 갱신하거나 가상 행사를 만들지 않는다. 다른 8개 분야, Supabase·관리자·광고·방문통계·연락처·자동화 설정은 수정하지 않는다. 비밀값이나 사용자 계정 정보는 보고서에 포함하지 않는다.

## 보고서 형식

한국어로 작성한다. 문제 수를 채우려고 지적을 만들지 않는다. `확인된 결함`, `사용성 개선 제안`, `취향 제안`, `미검증`을 구분한다.

1. 기준 버전, 실제 검토 시각, 실제 실행 모델(확인할 수 없으면 미확인), 사용한 도구와 제약.
2. 확인한 페이지·화면 폭·조작·결과 표. 확인하지 못한 것은 별도 표시.
3. 지적별 고유 ID(AG-001 등), 분류, 우선순위(P1 사용 불가/핵심 흐름 결함, P2 사용성·요구사항 누락, P3 다듬기), 경로·요소, 재현 단계, 실제/기대 동작, 근거(직접 확인한 코드 위치 또는 화면·기록), 권장 수정, 완료 조건.
4. 실행계획 보완안: 지적 ID, 변경할 실제 파일, 선행 작업, 수정 순서, 검증 시나리오. 구현하지 않는다.
5. 남은 미검증 항목·장애. 전체 승인 또는 완료라는 표현은 검토한 범위를 넘어서 사용하지 않는다.

사용자가 확정한 폰트·브랜드·색상은 재선정하지 않는다. 기존 구현 설명과 독립적으로 판단하되, 지적이 어떤 요구사항·관찰에 근거하는지 분명히 하라.
